# 기존 알려진 프로젝트 트랩 있으면 직접 추가 가능 (R19 자동 캡처 병행).

- context-leak: No Read sub-agent `*.output` files — tool noise pollutes main context. Judge the summary against the check written before dispatch, not its confidence; re-grep/re-read every cited file:line before acting on it. What the summary must cite: delegate packet, `src/superclaude/core/rules/RULES_DELEGATION.md`
- compaction-drift: Rules from session start degrade after ~50 turns auto-compaction. Long session, re-read critical rules if behavior drift
- rule-tag-vs-concept: When count rule occurrences, grep exact tag (e.g., \bR18\b), not concept name. "Verification" appear broadly but R15 appear once
- hypothesis-before-fix: Before propose bug fix, state top hypothesis AND specific evidence (file:line, command output, reproduction) that confirm. No guess from symptom shape.
- find-all-copies-first: Before edit file that may have duplicates (minified bundles, generated artifacts, vendored libs), grep full basename across repo + confirm copy count.
- hook-console-entry: Hooks run `superclaude hook <name>` (registry `src/superclaude/cli/hook_dispatch.py`, source `src/superclaude/scripts/`; by hand: pipe the JSON to it). `~/.claude/superclaude/scripts/` gets no new copies since 2026-09-05; a leftover dir is kept on purpose (hooks.md `hook-upgrade-live-session`)
- hook-placeholders-stale: `{{SCRIPTS_PATH}}` / `{{PYTHON_BIN}}` are written nowhere any more (`utils.SUPERCLAUDE_HOOK_MARKERS` keeps the first only to recognise pre-console-entry registrations) — a doc that prescribes them is stale
- askuserquestion-rejection-fallback: User rejects AskUserQuestion w/o explicit redirect msg → no re-ask, no stall. State top assumption ("Assuming X because Y → proceeding with bounded change"), execute minimal reversible action, surface diff so user can redirect if wrong
- grep-longline-blindspot: Grep `content` mode hides lines ~460+ chars (`N:[Omitted long matching line]`; older CC: no match). `description:` lines are this shape — a content-mode miss is NOT evidence of absence; sweep with `files_with_matches`. Repro (2026-08-02, ASCII): `src/superclaude/commands/prompt.md:2`
- windows-make-sync-broken: Windows `make sync-*`/`make deploy` 실패 가능 — `uv run superclaude install`이 `.venv\lib64` symlink 정리 시 권한 거부 (os error 5); `.venv/`에 `lib64 → lib` + `pyvenv.cfg`만 남음. Fix: AGENTS.md Tests의 venv rebuild. Fallback: `superclaude doctor --scope <s>` 후 `superclaude install --force --scope <s>` 직접
- codex-module-count-drift: `src/superclaude/` 아래 `.py` 추가/삭제 → `02_component_and_delivery_map.md` §1 module 카운트 stale → `tests/unit/test_codex_component_map.py::test_documented_count_matches_source` red. 같은 커밋에서 재계산: `uv run python -c "from pathlib import Path; print(len(list(Path('src/superclaude').rglob('*.py'))))"`
- uv-run-reverts-pip-upgrade: `uv pip install -e ".[dev]" --upgrade`로 올린 버전은 다음 `uv run`이 gitignored `uv.lock` 기준으로 default dep set을 auto-sync하며 조용히 되돌림 ("Uninstalled N packages" 한 줄, 실패 아님). 생존 여부 = lock의 default closure 포함 여부 (dev-extra로만 닿는 패키지만 생존). 로컬에서 진짜 올리려면 `uv lock --upgrade`로 lock을 먼저 옮길 것
- uv-lock-not-ci-pin: `uv.lock`은 gitignored이고 CI는 `uv pip install --system -e ".[dev]"`로 매번 최신 재해결 → lock은 CI를 고정하지 않음. 새 ruff 규칙은 lock과 무관하게 CI로 바로 들어옴
- lint-upgrade-attribution: Dep upgrade + lint failures land together → re-run the OLD tool (`uvx ruff@<old> check src/ tests/`) to pin attribution (2026-09-03: same 6 errors on old and new ruff → pre-existing). Only `ruff format`/`ruff check` gate (`make lint`, test.yml); a diff no gate checks is a red herring
- stale-number-copies: A count copied into an always-loaded doc (CLAUDE.md, AGENTS.md, auto-memory) goes stale. Cite the source, never the number: version → `pyproject.toml`; counts → `02_component_and_delivery_map.md` §1; pass count → none, `test_version_consistency.py` forbids one; volatile totals → run the tool
- venv-inherited-by-worktree: 2nd checkout, main `.venv` active: `uv pip install -e .` hits `$VIRTUAL_ENV` first, so the MAIN venv imports it. There: `unset VIRTUAL_ENV`, `--python <checkout>/.venv/.../python.exe`, verify `superclaude.__file__`. Repair main: same install, `--no-deps --python .venv/Scripts/python.exe`
- sync-scope-creates: `superclaude install --force --scope <s>` (and `make sync-user`) creates an install where none exists, not "refresh if present" — 2026-10-03 a user-scope sync on a local-only machine wrote SC import + hooks into `~/.claude/`, enabling SC everywhere. Check first: `superclaude doctor --scope <s>`
- plan-checklist-vs-status: `/sc:implement --plan` ticks each box as its step finishes; `status:` is separate — `complete` ticks none. Sub-agents never edit the plan doc; main loop ticks after verifying output. 2026-10-04: merged `status: complete` with 0/15 ticked; `tests/unit/test_plan_checklist.py` now reds that
- gitignore-unanchored-dir: A `.gitignore` dir rule without a leading `/` hides that name at any depth: a new or generated dir drops out of `git add`; tests pass on disk, a fresh clone fails. Anchor root-only rules (`/skills/`); dir missing from `git status` → `git check-ignore -v <file>`. Hit 2026-10-05, 10-08
