A content framework for Claude Code

The CLI copies framework files into Claude Code's content directories. Claude Code reads them at session start; the framework does not run a proxy or daemon.

Workflows you can invoke

Use /sc:brainstorm, /sc:plan, /sc:implement, and /sc:review across the development cycle.

Specialized agents and modes

Agent definitions and behavioral modes supply task-specific instructions when Claude Code loads the installed content.

Hook-enforced rules

Hooks help preserve workflow rules across sessions and tool calls while the installer merges with existing hook settings.

Optional integrations

The core works without MCP servers. Add supported integrations separately when a task needs them.

Install the CLI and content

No clone needed. Install uv if you don't have it, install the CLI from the latest release with it, then install the framework content into a scope.

@stable always points at the latest release. To pin one, replace it with that release's tag, @v<version>.

Want to change the framework and run your own version? See Customize your own copy.

Full installation and scope options ↗

  1. Install uv

    Skip this step if uv --version already works. Otherwise run the line for your OS, then open a new terminal.

    macOS / Linux

    curl -LsSf https://astral.sh/uv/install.sh | sh

    Windows

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

  2. Install the CLI

    uv tool install -p 3.13 git+https://github.com/ajitta/superclaude.git@stable

    If your shell then can't find superclaude, run this and open a new terminal:

    uv tool update-shell

  3. Install the content

    superclaude install --scope user

    For a committed team install, or personal files inside one project, run one of these in the project instead:

    superclaude install --scope project
    superclaude install --scope local

  4. Restart Claude Code

    Then run /sc:help to list the commands.

Update to a new release

Upgrade the CLI, then refresh each scope you installed:

uv tool upgrade superclaude
superclaude update --scope user

Try a command

After restarting Claude Code, begin with a specific task or use /sc:help to see the available commands.

/sc:brainstorm

Explore an underspecified request.

/sc:plan

Turn a task into an implementation plan.

/sc:implement

Work through the implementation.

/sc:review

Review code, a plan, or a design.

Run a command toward a goal

Claude Code's /goal sets a completion condition, and Claude keeps working turn after turn until a separate model judges it met. The condition is also Claude's first instruction, so a command named in it runs as part of the goal:

/goal sc:review the current diff, fix every finding, and review again until it reports none

Run /goal alone to check progress, or /goal clear to stop early.

Socratic plugin for Claude Code

One plugin from this repository's marketplace, socratic, holding two skills. It is separate from the framework: you install it inside Claude Code, without uv or the superclaude CLI.

Not the same as /sc:brainstorm, which turns a feature request into requirements and writes docs. These skills only ask questions and never implement anything.

Install on claude.ai or Codex ↗

  1. Add the marketplace

    Run this in Claude Code. It registers the marketplace, named ajitta-socratic, and installs nothing by itself.

    /plugin marketplace add ajitta/superclaude

  2. Install the plugin

    /plugin install socratic@ajitta-socratic

    Had the two earlier plugins, socratic-brainstorm and socratic-elenchus? Run /plugin marketplace update ajitta-socratic; they move to socratic at the next session.

  3. Use it

    Claude Code names a plugin's skill plugin:skill, so each command starts with socratic:. Add your idea after it, or just ask in words ("poke holes in this plan").

    /socratic:socratic-brainstorm

    Tests your idea one question at a time, draws out your options, adds up to three of its own, and ends with a verdict (sharpened, open, or refuted) and a short brief. Pick it when you want to leave with a plan.

    /socratic:socratic-elenchus

    The method of Plato's dialogues: "what is X?", premises you agree to, a contradiction built from them, and a definition you revise. No advice. Pick it to find out whether you know what you mean.

    To use both, settle the key word with elenchus first, then brainstorm. Plugins installed from user settings do not load in cloud sessions.

Customize your own copy

For developers who want to change the commands, agents, modes, or rules and run their own version. Clone the repository, point the superclaude CLI at your clone, and copy your edits into a scope. The content is markdown under src/superclaude/.

Developer guide in the README ↗

  1. Clone the repository

    This starts from the latest release. To keep your changes on GitHub, fork it first and clone your fork instead; its default branch is stable. Sending pull requests? Untick "Copy the stable branch only" when you fork and clone with -b master; they target master.

    git clone -b stable https://github.com/ajitta/superclaude.git
    cd superclaude

  2. Set up the environment

    uv venv -p 3.13
    uv pip install -e ".[dev]"

    Don't run uv sync: it removes the dev tools installed above, and the tests stop running.

  3. Run the CLI from your clone

    uv tool install --force --editable .

    This replaces a release install. superclaude now reads your clone, so later edits need no reinstall, but moving or deleting the clone breaks the CLI and its hooks. To go back to the release, rerun the CLI command from the Install section with --force.

  4. Edit, then sync into a scope

    After changing files under src/superclaude/, copy them into the scope you use, then restart Claude Code. For a project or local install, run it in that project with --scope project or --scope local.

    superclaude update --scope user

  5. Run the tests

    The markdown is tested too (counts, cross-references, structure), so run them after content edits as well.

    uv run pytest

Update to a new release

Commit your edits, then merge the new release into your clone. Resolve any conflicts with your changes, reinstall the CLI in case dependencies changed, and refresh each scope you installed:

git pull --no-rebase https://github.com/ajitta/superclaude.git stable
uv tool install --force --editable .
superclaude update --scope user
