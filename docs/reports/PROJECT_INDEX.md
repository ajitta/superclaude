## What this project is

A **content framework**: markdown files (commands, agents, modes, skills, MCP docs,
core config) installed into `~/.claude/` to configure Claude Code's behavior. It
ships a `superclaude` CLI and a pytest plugin for auto-markers. The markdown *is*
the product; the Python is the delivery mechanism.

- Package: `superclaude`, version from `pyproject.toml` (single source — a test enforces this)
- Python: `>=3.10` (dev env runs 3.12)
- Toolchain: **uv** only — never `pip` or `python -m pytest`

## Counting things

Inventory counts (commands, agents, skills, MCP servers, modules) are **derived
values**. They are not written here, because a doc copy goes stale silently.

```bash
# component counts, straight from the source tree
for d in commands agents modes skills mcp core; do
  printf '%s: %s\n' "$d" "$(find src/superclaude/$d -name '*.md' ! -name 'README.md' | wc -l)"
done

# python modules (keep docs/codex/.../02_component_and_delivery_map.md §1 in sync)
uv run python -c "from pathlib import Path; print(len(list(Path('src/superclaude').rglob('*.py'))))"

# managed MCP servers
uv run superclaude mcp --list
```

The authoritative written figures live in
`docs/codex/prompting_session_raw/02_component_and_delivery_map.md` §1 and are
enforced against the source tree by `tests/unit/test_codex_component_map.py`.
README counts are enforced by `tests/unit/test_version_consistency.py`.

## Daily commands

```bash
uv run pytest                          # must exit 0 — any red is a regression
make format                            # before committing
make deploy                            # CLI editable install (no content sync)
make sync-user | sync-project | sync-local   # content sync, scope-explicit
uv run superclaude install --list-all  # smoke-test CLI changes
```

**Do not run `uv sync`.** The dev toolchain lives in
`[project.optional-dependencies].dev`, not a default group, so `uv sync` prunes
it — black, ruff, mypy, pytest-cov and friends get uninstalled and the suite
stops running. Rebuild the venv with `uv venv && uv pip install -e ".[dev]"`.
